# 一致性验证与独立实现

**源码与数据**：[`crates/cofferwire-test/`](../../crates/cofferwire-test)、
[`independent/python/`](../../independent/python)、[`conformance/`](../../conformance)、
[`vectors/`](../../vectors)、[`fuzz/`](../../fuzz)、[`scripts/`](../../scripts)<br>
**运行位置**：本地验证、GitHub Actions、release evidence collection

## 1. 职责

本子系统把规范性要求映射到测试，维护语言中立 vectors，以独立实现发现规范歧义，
并把互操作、fuzz、故障注入、pilot、外审和 release 结果固化为可复核 evidence。它不
把测试覆盖率等同于安全证明，也不替外部参与者签署试点或安全审查。

## 2. 规范追踪

[`scripts/check_conformance.py`](../../scripts/check_conformance.py) 扫描规范 ID，并与
[`conformance/registry.json`](../../conformance/registry.json) 中的测试映射交叉检查。
新增 MUST 没有测试、重复 ID、未知测试或 revision 漂移都会失败；生成结果写入
[`coverage.json`](../../conformance/coverage.json)。application profile 使用独立 namespace，
不混入 core registry。

## 3. Public vectors 与 CDDL

`vectors/` 固定 queue/crypto/blob/receipt/offline exact bytes 和负向 case；
`profiles/vectors/` 固定 application profile fixture。`cofferwire-test` 从公开 JSON/CDDL
读取数据，不依赖生产路径生成 expected bytes。

## 4. 独立实现与互操作

[`independent/python/cofferwire_v1.py`](../../independent/python/cofferwire_v1.py) 是从公开
docs/spec/vector 编写的 clean-room queue-v1 client/relay。禁止 import/link Rust reference；
边界见 [`IMPLEMENTATION_NOTES.md`](../../independent/python/IMPLEMENTATION_NOTES.md)。

[`run_interop_matrix.py`](../../scripts/run_interop_matrix.py) 运行 Rust/Python client 与 relay
四种组合，并记录 source revision、artifact digest、trace IDs 和 differences。

## 5. Hostile input 与故障恢复

- `fuzz/` 覆盖 queue/blob decoder、hostile proof 和 relay transition；定时 workflow 使用
  明确预算并归档 crash artifacts。
- relay/client/daemon tests 覆盖进程 kill、commit 前后、disk full/read-only/busy、时钟
  跳变、并发、backup/restore 和 schema migration。
- [`collect_fuzz_evidence.py`](../../scripts/collect_fuzz_evidence.py) 与
  [`collect_durability_evidence.py`](../../scripts/collect_durability_evidence.py) 绑定运行
  revision、toolchain、预算和具名测试结果。

## 6. 外部证据与发布

| 工具 | 契约 |
|---|---|
| [`validate_family_tree_pilot.py`](../../scripts/validate_family_tree_pilot.py) | 拒绝非物理设备、共享 relay 运营者、短离线、遗漏场景和 protocol exception |
| [`build_review_bundle.py`](../../scripts/build_review_bundle.py) | 从指定 Git commit 构建规范化、可重复的审查归档 |
| [`validate_external_review.py`](../../scripts/validate_external_review.py) | 强制独立 reviewer、完整 scope 和 finding disposition |
| [`build_release_artifacts.py`](../../scripts/build_release_artifacts.py) | 生成 source/docs/spec/vector/conformance/binary/SBOM 工件与 checksums |
| [`validate_release_candidate.py`](../../scripts/validate_release_candidate.py) | 验证十 gates、同 revision evidence、所有 digest 与正式签名 |

review/release builder 通过 `scripts/cofferwire_tools/archive.py` 共用 Git tree 读取、文件模式、
规范化 tar metadata、版本和 queue scope revision，避免可复现性规则在多个 CLI 中漂移。

## 7. 常用验证层级

1. 局部 crate/unit test；
2. `cargo test --workspace` 与 Python suites；
3. conformance registry 和四组合 interop；
4. fmt、Clippy `-D warnings` 与 fuzz target build；
5. 按风险运行持续 fuzz、fault evidence、真实 pilot、external review 和两环境 release build。

完整 release gate 定义只见 [`TESTING.md` §12](../../TESTING.md#12-release-gates)。

# 外部接口

本文件是 reference daemon 与诊断 transport 的工程接口索引。协议字段、canonical bytes、
command/status 数值和认证覆盖的规范性来源仍是 [`../spec/`](../spec/README.md)。

## 1. 接口一览

| 方法 / transport | 协议 | 请求 | 成功响应 | 实现 |
|---|---|---|---|---|
| `POST /v1/frame` | queue-v1 HTTPS | 一个完整 queue frame；必须使用注册 media type | 一个完整 queue response frame | [`post_frame`](../../apps/cofferwired/src/transport.rs) |
| `GET /v1/ws` | queue-v1 WebSocket | binary message，每条一个完整 frame；协商注册 subprotocol | binary response message | [`websocket_session`](../../apps/cofferwired/src/transport.rs) |
| `POST /blob/v1/frame` | blob/1 HTTPS | 一个完整 blob frame；使用 blob media type | 一个完整 blob response frame | [`post_blob_frame`](../../apps/cofferwired/src/transport.rs) |
| `GET /blob/v1/ws` | blob/1 WebSocket | binary message，每条一个完整 blob frame | binary response message | [`websocket_session`](../../apps/cofferwired/src/transport.rs) |
| `GET /healthz` | 运维 | 无 body | HTTP 204；只表示进程可响应 | [`router`](../../apps/cofferwired/src/transport.rs) |
| stdin/stdout line | queue-v1 conformance | `<unix-seconds> <frame-hex>` | 一行 response hex | [`cofferwire-line-relay.rs`](../../apps/cofferwired/src/bin/cofferwire-line-relay.rs) |

注册 media type、WebSocket subprotocol 和 frame 上限由
[`docs/spec/09-transport-bindings.md`](../spec/09-transport-bindings.md) 与对应源码常量共同
约束，不在本设计书重复数值。

## 2. Queue 命令契约

| 命令 | 认证角色 | 前置条件 | 主要结果 |
|---|---|---|---|
| CREATE_QUEUE | sender | QueueId、双方 Principal 和 limits 合法 | 创建或确认完全相同配置；冲突配置拒绝 |
| SEND | sender | queue 存在、权限匹配、容量/大小/TTL 合法 | durable accept、exact duplicate 或明确错误 |
| FETCH | recipient | queue 存在且权限匹配 | 最早可投递消息或 empty；投递状态持久化 |
| ACK | recipient | 指定消息已经投递且未到期 | 与校验同事务删除目标消息 |
| DELETE_QUEUE | recipient | queue 存在且权限匹配 | 原子删除 queue 及其 message |

完整字段和错误语义见 [`docs/spec/05`](../spec/05-wire-format.md) 与
[`docs/spec/06`](../spec/06-queues.md)。HTTP 业务错误通常仍返回可解码 protocol response；
不支持的 media type、body layer 拒绝、过载和内部存储不可用使用 HTTP 层状态。

## 3. Blob 命令契约

| 命令族 | capability | 契约 |
|---|---|---|
| BEGIN_UPLOAD / PUT_CHUNK / COMMIT | upload | staged chunks 完整且身份一致后才原子可见 |
| GET_MANIFEST / GET_CHUNK | download | 只读取已 commit、未过期且 grant 有效的对象 |
| RENEW | renew | 只改变对应 grant 的可用期，不改变 ciphertext identity |
| DELETE | delete | 撤销对应 grant；当前不承诺物理删除共享 ciphertext |

字段、状态和 exact frame 见 [`docs/spec/07`](../spec/07-blobs.md)；客户端恢复流程见
[`40_客户端状态机.md`](40_客户端状态机.md)。

## 4. HTTPS 示例

以下示例只展示 transport 形态，`request.cbor` 必须是客户端按规范生成并认证的完整
binary frame：

```sh
curl --fail-with-body \
  --header 'Content-Type: application/cofferwire' \
  --data-binary @request.cbor \
  --output response.cbor \
  https://relay.example/v1/frame
```

TLS 验证不得在生产环境关闭。健康检查不能证明 SQLite 写入、外部可达性或端到端消息
交换正常；运营检查见 [`90_部署与运维.md`](90_部署与运维.md)。

## 5. Library 接口

嵌入式调用可直接使用 [`RelayService::exchange_frame_at`](../../apps/cofferwired/src/lib.rs)
与 [`exchange_blob_frame_at`](../../apps/cofferwired/src/lib.rs) 运行确定时钟的完整 frame；
这两者用于 conformance，并不绕过 decode/auth/replay/storage。更低层的
[`DurableRelay`](../../crates/cofferwire-relay/src/durable.rs) 方法要求调用者已完成认证，
不应直接暴露给不可信网络输入。
